# aequorOS evidence pack for the Bank of Ghana application

Prepared 8 October 2026 for the pilot bank's risk and procurement teams, as
requested in [#356](https://github.com/CedynGroup/aequorOS/issues/356).
It describes what aequorOS does today. It is not an approval, a certification
or a signed assurance.

Each statement cites its source by file and line number in the aequorOS code
repository, written as `file:line`, at code version
`7c3fecf2a61a45adff04bc9f823d974ee11e00c6`. Controls added since that version
are described in the [transport security contract](../../backend/docs/transport_security.md),
the [bank encryption contract](../../backend/docs/bank_encryption.md) and the
[tamper-evident records contract](../../backend/docs/tamper_evident_records.md).

## 1. Application documents and responsibility

This pack supplies aequorOS's technical input to the bank's application. The BoG
[Outsourcing Directive, November 2024](https://www.bog.gov.gh/wp-content/uploads/2024/11/BOG-Outsourcing-Directive.pdf),
paragraph 87 and Annexure V, requires application evidence and a register of
outsourced services. The bank's own risk assessment, due diligence, risk
framework, register and contract remain with the bank risk team.

### 3.1 Connections to outside services

- **AI connections:** Anthropic is called through its own software kit, with a
  specific access key, a time limit and a limit on retries
  (`backend/app/services/ai/client.py:319`). OpenAI is called at
  https://api.openai.com/v1, using its responses service
  (`backend/app/services/ai/openai_model.py:70`). Google is called at a
  configured address (`backend/app/services/ai/google_model.py:111`, `:172`).
- **Signing key custody:** to sign, the system sends OpenBao's signing service a
  fingerprint of the document, a reference to the key and the signing settings.
  The fingerprint is a SHA-256 hash, sent as encoded text. Certificate checking
  is on by default, or uses a configured set of trusted certificates
  (`backend/app/attestation/service/openbao.py:246`, `:566`).
- **Staff support:** the staff member's browser sends requests to the console's
  own server. That server forwards the staff member's login token and the request
  to the staff server. The staff server decides what is allowed
  (`console/app/api/op/[...path]/route.ts:24`, `:38`, `:55`;
  `console/.env.example:7`).
- **Public enquiries and analytics:** when set up, contact form messages go to
  Resend and to the chosen recipient. When analytics is enabled, the tracking
  script contacts Cloudflare (`frontend/app/api/contact/route.ts:78`, `:114`;
  `frontend/components/Analytics.tsx:27`). This is separate from the import of
  bank financial data.

## 6. Incident detection

The system defines alert conditions, including unusual sign-in activity and
storage failures. Each produces a message in the operational logs. Sources:
`backend/app/core/observability.py:80`; `backend/app/core/logging.py:40`.

## 7. Data retention when a bank leaves

When a bank leaves the live service, its data is retained. Deletion of a bank's
storage is limited to testing and development. Source:
`backend/app/storage/provisioning.py:99`.

## 8. Recovery

A database restore test (a "drill") was run on a local machine on 22 August 2026. The database step took about 123 seconds at minimum. The drill checked
134 tables and 12,001,905 rows by row count and fingerprint, and checked that
banks' data stayed separate. Sources: `README.md:169`;
`docs/audit/00_evidence_package_index.md:93`.
