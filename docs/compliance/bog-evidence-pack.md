# aequorOS evidence pack for the Bank of Ghana application

Prepared 8 October 2026 for the pilot bank's risk and procurement teams.
This is the draft requested in [#356](https://github.com/CedynGroup/aequorOS/issues/356).
It is based on the aequorOS source code.
It is not an approval, a certification or a signed assurance.

This pack covers everything the source code can show. Items marked "To confirm"
are facts about how aequorOS runs the service. aequorOS must answer them before
the bank submits its application. Legal wording is left to counsel.

How to read this pack:

- "Built" means the feature exists in the cited source code.
- "Planned" means the control did not exist in the version of the code we reviewed.
- Default settings in the code, and notes in deployment files, do not show how
  the live service is actually set up.
- We did not query any live (production) system for this pack.
- Each source is cited by its file and line number in the aequorOS code
  repository, written as `file:line`. The bank's final copy must include the
  reviewed code version and dated evidence from the live deployment.

Code version reviewed (the "baseline"): `7c3fecf2a61a45adff04bc9f823d974ee11e00c6`.

This pack describes the code as it stood at that baseline. It is not a list of
everything built today. Controls added since then are described in the
[transport security contract](../../backend/docs/transport_security.md), the
[bank encryption contract](../../backend/docs/bank_encryption.md) and the
[tamper-evident records contract](../../backend/docs/tamper_evident_records.md).
Those documents do not provide evidence from the pilot deployment. They do not
answer any of the owner questions below. Before submission, check this draft
against the release under review and attach the dated confirmations. Keep the
baseline so that each statement can still be traced.

### 3.1 Connections to outside services

- **AI connections:** Anthropic is called through its own software kit, with a
  specific access key, a time limit and a limit on retries
  (`backend/app/services/ai/client.py:319`). OpenAI is called at
  https://api.openai.com/v1, using its responses service
  (`backend/app/services/ai/openai_model.py:70`). Google needs its address to be
  set up (`backend/app/services/ai/google_model.py:111`, `:172`). Web addresses
  and software defaults do not show where processing happens. Q08 must name
  every enabled vendor and any backup destination.
- **Signing key custody:** to sign, the system sends OpenBao's signing service a
  fingerprint of the document, a reference to the key and the signing settings.
  The fingerprint is a SHA-256 hash, sent as encoded text. Certificate checking
  is on by default, or uses a configured set of trusted certificates
  (`backend/app/services/attestation/openbao.py:246`, `:566`). In the committed
  setup, the vault's own connection is unencrypted and sits behind a proxy on the
  same server (`deploy/openbao/docker-compose.openbao.yml:84`). Q02, Q12 and Q13
  must establish the real server, who has authority over the keys, and how both
  sides of that proxy are protected.
- **Staff support:** the staff member's browser sends requests to the console's
  own server. That server forwards the staff member's login token and the request
  to the staff server. The staff server decides what is allowed
  (`console/app/api/op/[...path]/route.ts:24`, `:38`, `:55`;
  `console/.env.example:7`). Q07 and Q10 must cover the network controls on this
  route and what staff can read or change.
- **Public enquiries and analytics:** when set up, contact form messages go to
  Resend and to the chosen recipient. When analytics is enabled, the tracking
  script contacts Cloudflare (`frontend/app/api/contact/route.ts:78`, `:114`;
  `frontend/components/Analytics.tsx:27`). Q04, Q05 and Q07 must establish
  whether these are in use, where processing happens and how long data is kept.
  This is separate from the import of bank financial data.
