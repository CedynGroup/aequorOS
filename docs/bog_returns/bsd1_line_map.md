# BSD1 — Liquidity Reserve Return: line / cell map

**Official workbook:** `FORM BSD1 REVISED.xls` · **Frequency:** weekly · **Time limit:** 9 days · **Basis:** solo — **Ghana branches only** (Guide, General Notes §1)

**Sheets (official order):** `BSD1 `, `BSD1-Annex1`, `BSD1-Annex2`, `BSD1-Annex3`

Generated from `bog_forms/linemaps/bsd1.py` + `layouts/BSD1.json` (row tables are generated — regenerate, do not hand-edit them).

Status legend — **mapped**: fed from platform data via the named resolver (a mapped cell can still export blank/`input_required` at run time when the resolver finds no data for that day — see the ladder rule); **input_required**: bank must supply (no canonical source); **coa-mapping**: bank-specific chart-of-accounts split required. **Unit** column: `sheet unit` = resolver returns base cedis and the exporter divides by the sheet's ¢'Million; `unscaled` = the value is already in the cell's own unit (native currency units, rates, counts).

### Time axis (from the template's own header formulas)

- `B3` PERIOD = the week's **Wednesday** = the platform reporting date (`period_end`); `B4 = B3+9` is the filing deadline (Guide: weekly, 9 days).
- **DEPOSITS block (rows 10–26) = PREVIOUS week**: `B7 = B3-13` … `H7 = B3-7` — column `B` (THU) is reporting date − 13, … `H` (WED) is reporting date − 7. The primary/secondary reserve requirement (rows 73–77) is struck against this lagged deposit base — the template's own arithmetic.
- **LIQUID ASSETS + MEMORANDA (rows 32–95) = CURRENT week**: `B28 = B3-6` … `H28 = B3` — `H` (WED) is the reporting date itself.
- `I` = TOTAL of the seven days, `J` = `I/7` AVERAGE; rows 16/21/22/25/26/35/36/40/44/51/52/56/65/66/88/93 are sub-totals; rows 67–70 are the actual reserve ratios (`20/12`, `18/7`, `19/11`, `27/12` × 100); rows 73–77 the required reserves (9% / 9% / 9% / 35% / 15% of the deposit base); rows 80–85 the surplus/deficit. All 2,844 formula cells (including the stray copies BoG left in columns K…IV) are BoG's and are evaluated, never re-implemented.
- The catalogue's weekly anchor (`WEEKLY_ANCHOR_WEEKDAY`, Friday) is a platform convention for the calendar; **BSD1's own grid ends on Wednesday**. Whatever weekday the reporting date falls on, the resolvers place it in column `H` and step back one day per column, exactly as `B28 = B3-6` does.

### Daily source — the EOD position ladder (`bsd1.daily`)

The platform's daily state is `canonical_position_snapshots`: one immutable snapshot per position per business `as_of_date` when the bank ingests daily (core-banking adapters, API push). `bsd1.daily` sums the snapshots whose `as_of_date` **is exactly the column's day** (current generation only), applying the row's filters (position type, counterparty type, `deposit_account_type`, `rate_type`, snapshot attributes, currency). Cedi values use the raw balance for base-currency positions and the ingested `attributes.balance_ghs` for foreign-currency ones — the same convention fact derivation applies.

**Honesty rule.** A day for which the ladder holds **no snapshot at all** returns `None` ⇒ the cell exports blank with status `input_required` ("daily balance — EOD ladder required"). A balance is **never** copied from a neighbouring day: on a month-end-only book six of the seven columns stay blank rather than showing one balance seven times (which would fabricate the weekly average). A day that has rungs but no matching positions is a genuine `0`.

**Reporting-date fallback (`facts`).** On the reporting date only (the one day the monthly `bank_facts` spine also describes) a row may name a period-end fact set that fills column `H` when the ladder has no rung there: cash on hand ← `cash_vault`; BoG current account ← `bog_required_reserves + bog_excess_reserves` (both are balances on the current account with BoG — the primary reserve is met by that account); total deposits ← the five `balance_sheet` deposit facts. The previous-week DEPOSITS block never touches the reporting date, so it is ladder-only.

**Attribute contract** (snapshot `attributes` keys the row filters read — the same conventions as the BSD2 line map so one ingestion feeds both): `instrument` ∈ {`bog_bill`, `bog_bond`, `tbill`, `gog_bond`, `ggilb`, `tor_bond`, `gog_stock`, `cocoa_bill`, `cotton_bill`, `grains_bill`, `ssnit_educational_bond`, `finsap_bond`, `certificate_of_deposit`, `special_deposit`, `margin_against_contingent`}; `tenor_days` (28/30/56/91/182), `tenor_years` (1/2/3); `institution_class=discount_house` + `tenor=call`; `issuer_class` ∈ {`soe`, `private`}. Numeric attributes match whether the source encoded them as JSON numbers or strings.

**Ghana branches only.** Positions carry `attributes.branch_id` from ingestion, but the platform has no branch → country link (the Outlet register carries no `branch_id` join and no country column), so the Guide's branch restriction **cannot be applied honestly today**: every daily figure is whole-bank. `FormSpec.ghana_branches_only` flags the form; the filter is a framework/data ask below.

## Framework / data asks

- **Branch → country attribute.** To honour 'Ghana branches only' the ladder resolver needs either a `branch_country` snapshot attribute or an Outlet-register join keyed on `attributes.branch_id` (the Outlet model has neither a `branch_id`/`outlet_number` link contract nor a country column). `bsd1.daily` accepts an `attribute_eq` filter today, so `{'branch_country': 'GH'}` can be switched on the day ingestion carries it — no line-map change needed beyond adding the filter.
- **Daily GL ladder for the primary-reserve rows.** Cash on hand and the BoG current account are GL-classified at period end (`fact_derivation._classify_gl_assets`); the canonical GL table carries an `as_of_date` per row, but the classifier runs only in fact derivation. Running that classifier over the daily GL rungs (or emitting daily `balance_sheet` facts) would feed rows 17–19 for all seven days from the GL instead of relying on `CASH` positions.
- **Core `positions.sum` foreign column sums raw balances** (position currency units) rather than `attributes.balance_ghs`; `bsd1.daily` converts. Not changed here (out of scope) — flagged.
- **Reporting-date convention.** The template's week ends on Wednesday; the registry's weekly anchor is Friday. The resolvers are anchor-agnostic (column `H` = the reporting date), but the calendar should strike BSD1 on Wednesdays for the header formulas `B7 = B3-13` / `B28 = B3-6` to read as BoG intends.
