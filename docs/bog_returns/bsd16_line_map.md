## 1. What the template is, and how it is bound

A 50-row station/branch roster whose data cells are **BLANK in the official file**; the extractor captured only the row ordinals `A7:A56` (1–50, numeric) as input cells and the 51 formulas. Every data cell is bound explicitly with `_common.grid_lines`:

| Rows | Official data columns bound (column key → letter) | Template formulas (never bound) | Not bound |
|---|---|---|---|
| 7–56 (stations 1–50) | `serial`→A (captured ordinal, `constant` 1–50, unscaled) · `station`→B Station / Branch (text) · `cards_issued`→C No. of Cards Issued (unscaled count) · `min_withdrawal`→D Minimum withdrawal made ¢ · `max_withdrawal`→E Maximum withdrawal made ¢ | `F7:F56 = D + E` (the template's per-row "Total Withdrawals ¢" — BoG's arithmetic as shipped, reproduced verbatim) | — |
| 57 TOTAL | `min_withdrawal`→D57 · `max_withdrawal`→E57 (bordered, no formula in the official file) | `F57 = SUM(F7:F56)` | `C57` is a label cell (`+`) in the official file |
| 59–63 | — | — | attestation text / signature lines (labels) |

**Sources — data-gap closure (2026-08-16): the `atm_operations` reference dataset.** No ATM, card or channel entity exists on the platform (searched `app/models` / `app/domain`; the corporate-profile outlet register lists branches but not which host an ATM), so the source is the bank's own monthly ATM register pushed / uploaded through the Data Engine (`docs/data_engine/datasets/atm_operations.md` — one row per terminal for ONE reporting month, `as_of_date` = month-end; BSD16 reads the latest batch on/before the period end). Station row `7 + i` binds the `i`-th register row in file order through `refs.field index=i` — `station` → B, `cards_issued` → C (unscaled count), `min_withdrawal_ghs` → D, `max_withdrawal_ghs` → E (cedis; ¢'Million at export); D57 / E57 bind `refs.sum` over the whole register (the bank's own column totals — the official total row carries no formula); F stays BoG's `=D+E` / `=SUM(F7:F56)`. Fewer than 50 terminals leaves the tail rows blank (`input_required`, not an error); more than 50 shows the first 50 while the totals cover the whole register. Before the register is ingested every cell resolves to `input_required` at generation, exactly as before. The ordinals are the template's own values and are kept.

## 2. Documented decisions

| Item | Decision |
|---|---|
| Sheet unit | catalogue: ¢'Million (template header). `cards_issued` is a count → `unscaled=True`; withdrawals scale with the sheet. |
| `F = D + E` | the official file sums minimum + maximum withdrawal into "Total Withdrawals ¢" — questionable, but it is BoG's template formula and is evaluated as shipped (never re-implemented). With blank inputs it evaluates to 0. |
| Row 57 D/E | bordered cells with no formula in the total row: bound `refs.sum` over the register's `min_withdrawal_ghs` / `max_withdrawal_ghs` — the bank's own column totals, consistent with BoG's `F57 = SUM(F7:F56)` whenever the estate fits the 50-row grid (data-gap closure 2026-08-16; previously `input_required`). |
| Ordinals A7:A56 | captured numeric inputs → `constant` with the template's own value so the export reproduces the "1…50" column (unscaled: 1, not 1e-6). |
| Station order | `refs.field` without `order_by` keeps ingestion order — the bank controls the roster order by the order of its file (no ranking rule of ours). |
| Register grain | one reporting month per push (`as_of_date` = month-end); a multi-month file would be read as one month's roster — see the dataset doc. |
