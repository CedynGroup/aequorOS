## 2. Data-gap closure — the `capital_expenditure` register (2026-08-16)

The Guide defines every BSD10 figure as a half-year **cash flow** by asset class — expenditure incurred (A–C), work in progress (D), commitments (E), authorisations (F), forecasts (G, split 0–3 / 3–6 months) and disposal receipts (H) — "without deductions for depreciation, amortisation or obsolescence". The platform held fixed assets only as a **stock** (one GL `ASSET` balance, no asset-class attribute), so until 2026-08-16 every cell was `input_required` naming the capital-expenditure register the bank must supply. That register now exists as the reference dataset **`capital_expenditure`** (`docs/data_engine/datasets/capital_expenditure.md`; schema `reference_schemas/capital_expenditure.py`; ingested through the Data Engine — app upload or API push, `docs/API_INTEGRATION.md` §3.5): one row per `(period_end, asset_class)` carrying the Guide's own fields — `additions_purchased_ghs` (A), `additions_finance_lease_ghs` (B), `additions_hire_purchase_ghs` (C), `capital_wip_ghs` (D), `contracted_not_provided_ghs` (E), `authorised_not_contracted_ghs` (F), `forecast_next_6m_ghs` (G), `disposal_proceeds_ghs` (H), `forecast_0_3m_ghs` / `forecast_3_6m_ghs` (rows 16 / 17) — plus the period-end stock that fills BSD2 item 12 from the same rows.

Binding: cell (row, column) = `refs.sum {kind: capital_expenditure, value_field: <row field>, filters: {asset_class: <column classes>}}` over the **latest** register on/before the reporting date. Column classes (`reference_schemas.capital_expenditure.BSD10_COLUMN_CLASSES`): Land and Buildings = `land_buildings` + `staff_land_premises` (BSD2 splits bank vs staff premises; BSD10 does not); Furniture and Equipment = `furniture_equipment`; Computers = `computers`; Other Office Equipment = `other_office_equipment`; Motor Vehicles = `motor_vehicles`; the BSD2-only class `other_property_legal_rights` is not summed anywhere on BSD10 (Guide: intangibles excluded). Nothing is derived from a stock balance — every figure is the bank's own half-year figure; blank until the register is ingested at all, `0` for a class with no row or an omitted optional field. **One period per push** (batch `as_of_date` = `period_end`).

## 8. Framework asks

- **Per-column `RowSource`.** `leaf_lines` binds one `RowSource` per row across all `value_columns`; a grid whose columns are categories (asset classes here, tenors / currencies elsewhere) needs a per-column binding — the map works around it with one `leaf_lines` call per column (five `LineSpec`s per official row). A `column_params: {column_key: {…}}` overlay on `RowSource` (merged into `params` per cell) would let one declaration bind the row.
- **Row 13 vs rows 16 + 17.** The template holds "G. Forecast to be acquired in next six months" AND its 0–3 / 3–6 split as separate inputs (row 18 totals only the split); the register carries all three (`forecast_next_6m_ghs`, `forecast_0_3m_ghs`, `forecast_3_6m_ghs`) and the schema validates G = 0–3 + 3–6 when all three are given — the platform never infers one from the others.
