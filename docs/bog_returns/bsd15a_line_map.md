## What the form asks and where each figure comes from

FORM BSD15A (weekly, 9 days) is the bank's DOMESTIC tariff: `Domestic charges
of banks` (22 numbered items — COT, ledger fees, maintenance fees, drafts,
returned / stopped cheques, transfers, lending fees, statements, clearing,
standing orders, salary / pension processing, closures, safe custody, cheque
books, ATM, Sika card) and `Range of pdts i.r.o sav & cur ` (initial deposit,
minimum operating balance, maintenance / penal / transaction fees per savings
product S1–S7, current product C1–C3 and foreign accounts; "Amounts in Cedis").

**Data-gap closure (2026-08-16) — the tariff register is a Data Engine dataset.**
Every tariff cell reads the bank's `tariff_schedule` reference dataset
(`docs/data_engine/datasets/tariff_schedule.md`; uploaded or pushed through
the Data Engine, one row per official tariff cell) through
`refs.field {kind: tariff_schedule, filters: {form, sheet, row_key}, field:
charge_value}` — the row is addressed by the official form / sheet code
(`DOMESTIC` / `RANGE`) / `row_key` (`"<item>.<n>"`, generated by
`linemaps/bsd15a.tariff_row_keys`, e.g. `1.1` = COT minimum, `S1.1` = Savings
S1 initial deposit) and the cell carries that row's `charge_value` — text as
published on the Domestic sheet, a cedi amount (`numeric=True`, unscaled) on
the Range sheet. Until the register is ingested every cell resolves to
`input_required` ("tariff register required") at generation, the structure
exports verbatim and the Completion notes list every line; once ingested the
cells are `mapped` (the Sample Bank register flips 168 + 75 of them —
`tests/services/data_gaps/test_tariff_schedule.py`; the two Range block
sub-headings `FX.1` / `FX.6` take no amount by design). The item numbers 1–22
in column A stay the template's constants. Sharp edge: the Data Engine's type
coercer reads `N/A` / `Nil` / `-` / `none` as null sentinels, so a tariff
that is free or not offered must be spelt out (`Free`, `Not applicable`).

**Value cells.** The templates ship the value grids empty and without column
headers (row 7 / row 10 carry a numeric format across C..S / B..R but no
text). The first value column is bound: `C` on the domestic sheet (item text
in B), `B` on the range sheet (item text in A). **Which rows take a value:**
every labelled row of the schedule except a heading that introduces
sub-lines — a numbered item heading (captured item number in column A, or a
`n. ` label prefix) or a colon-terminated group label — when it is followed
by sub-lines; childless headings take the value. When in doubt a row is
bound (a spare blank input cell costs nothing; a dropped official line would).
`linemaps/bsd15a.tariff_rows` is the single implementation (BSD15B reuses it).

  (form · sheet · row_key · charge_value · charge_basis · min / max · currency ·
  effective_from), read through the generic `refs.field` resolver — no
  form-specific resolver was needed.
* **Null-sentinel text.** The ML-ETL type coercer turns `N/A` / `Nil` / `-` /
  `none` into `None` on every ingested value, reference rows included. For a
  free-text tariff register those are legitimate answers; a per-schema
  "verbatim text" field flag (or exempting reference payload text) would let a
  bank type them. Documented as a data rule for now.
* **Value-column headers.** The official templates carry no header text over
  the value columns (BSD15A: C..S formatted, bordered A–F; BSD15B: B..T
  formatted, E..Q percent-formatted). The first value column is bound; if BoG
  intends separate Min / Max / Basis columns, the layout extraction cannot
  tell — confirm with BSD and re-point `value_columns` (one line).
