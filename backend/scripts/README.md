# Backend script index

Discovery guide, not a production runbook. Owners below are code areas, not
authorization to run a tool. Read the linked script's header and argument parser
before use; do not run an operator script merely to prove it is reachable.

Prefer the named `mise` task from the repository root. Otherwise, from `backend/`,
`python NAME` below means `uv run python -m scripts.NAME`, with the arguments in
that script's usage. Entries marked **helper** are imported by their caller, not
standalone commands. Dependencies come from the locked backend environment.

**Output safety:** read-only does not mean public. Keep tenant reports, filings,
backup manifests, object keys, credentials and logs in access-controlled storage
outside tracked source; an ignored directory alone is not access control. Share
only reviewed, redacted evidence. Use environment-based credentials where
supported, never literal secrets in commands or committed examples. The push
clients currently require `--token`, which exposes it in process arguments; do
not use them in shared or recorded sessions. Account provisioning can print a
password once: do not capture that output in shared logs.

## Mutating operator tools

Select and authorize the target explicitly. This index supplies no production
credentials, activation procedure or permission to bypass application workflows.
See the public [bank encryption](../docs/bank_encryption.md) and
[tamper-evident records](../docs/tamper_evident_records.md) contracts for safeguards.

**Storage purge warning:** `reset_uploaded_data.py --purge-storage` deletes all
current objects in the configured bucket, irrespective of the selected bank.
It can affect other tenants sharing that bucket.

The pytest/CI **helpers** below are activated by the test configuration and
workflow, not by executing each file. Their effects follow the selected suite:
unit execution refuses database acquisitions; integration execution writes only
to disposable test databases. Observation/report directories are generated
evidence, not source or permission to inspect live data.

- Suite selection/scheduling: [test_suites_plugin.py](test_suites_plugin.py),
  [ci_postgres_plugin.py](ci_postgres_plugin.py), [ci_unit_scheduler.py](ci_unit_scheduler.py).
- Database contracts/tracing: [database_contracts.py](database_contracts.py),
  [database_observation_plugin.py](database_observation_plugin.py),
  [database_observation.py](database_observation.py), [database_events.py](database_events.py).
- Child-process instrumentation: [ci_database_children.py](ci_database_children.py),
  [database_child_startup.py](database_child_startup.py),
  [isolated_database_child.py](isolated_database_child.py) and
  [ci_no_database](ci_no_database/__init__.py).
  `ci_database_children.python_path` adds `scripts/ci_no_database` and the backend
  root to inherited `PYTHONPATH`. Python then automatically imports
  [sitecustomize.py](ci_no_database/sitecustomize.py), which installs instrumentation
  when `CI_NO_DATABASE_ATTEMPTS` or `CI_DATABASE_OBSERVATIONS` is set. It is an
  active startup hook, not an unused CLI; isolated `-I`/`-S` inline children use
  the separate bootstrap.
